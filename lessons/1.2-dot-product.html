Goals学习目标Learning goals

  • 会算点积，知道结果是一个数，不是向量。
  • 读懂点积的符号：正 = 同一侧（夹角小于 90°），0 = 垂直，负 = 相反一侧。用它判断"在前面还是后面"。
  • 用点积求夹角和投影，知道什么时候必须先归一化。
  • 看懂光照里最常见的一行：亮度 = max(0, n · l)。
  • Compute a dot product and know the result is a number, not a vector.
  • Read its sign: positive = same side (angle under 90°), 0 = perpendicular, negative = opposite side. Use it to tell "in front or behind".
  • Get angles and projections from it, and know when you must normalize first.
  • Understand the most common line in lighting: brightness = max(0, n · l).

Intuition直觉Intuition

点积回答一个问题：两支箭头有多"同向"？想象正午的太阳从 b 的方向垂直照在 b 所在的直线上，a 在这条线上投下的影子有多长，再乘以 b 的长度，就是 a · b。a 和 b 指向同一边，影子落在正方向，点积为正；两者垂直，影子缩成一个点，点积为 0；指向相反，影子落在反方向，点积为负。

The dot product answers one question: how much do two arrows point the same way? Drop the shadow of a onto the line through b, at right angles. The shadow's length times the length of b is a · b. If a and b point to the same side, the shadow lands forward and the dot product is positive; perpendicular, the shadow shrinks to a point and it is 0; opposite, the shadow lands backward and it is negative.

图形学里点积到处都是：表面朝不朝光（光照）、物体在不在相机前面（裁剪）、敌人在不在视野里（游戏 AI）、三角形是正面还是背面（背面剔除）。它们都是同一个判断：看点积的正负或大小。

Graphics uses it everywhere: does a surface face the light (lighting), is an object in front of the camera (clipping), is an enemy inside the field of view (game AI), is a triangle front- or back-facing (back-face culling). Each one is the same test: look at the sign or size of a dot product.

Math数学Math

点积有两种写法，它们相等，这是整节课的核心：

The dot product has two forms, and they are equal. That equality is the whole lesson:

a · b = aₓbₓ + a_y b_y + a_z b_z        ← 代数：逐分量相乘再相加 / algebra: multiply components, add
a · b = |a| |b| cos θ                    ← 几何：θ 是两者夹角 / geometry: θ is the angle between them

第一种好算，第二种好理解。由它们可以推出所有用法：

The first is easy to compute, the second easy to interpret. Every use follows from them:

cos θ = (a · b) / (|a| |b|)              ← 求夹角 / angle
a · b̂ = |a| cos θ                        ← a 在 b 方向上的投影长度（带正负）/ signed length of a along b
proj_b(a) = (a · b / b · b) · b          ← 投影向量 / projection vector
a · a = |a|²                              ← 长度的平方，不用开方 / squared length, no square root

符号表：θ < 90° 时 cos θ > 0，点积为正；θ = 90° 时为 0；θ > 90° 时为负。|a| 和 |b| 永远不是负数，所以点积的符号只由夹角决定，判断前后左右时不需要归一化。

Sign table: for θ < 90°, cos θ > 0 and the dot product is positive; at θ = 90° it is 0; above 90° it is negative. |a| and |b| are never negative, so the sign depends only on the angle, and a front/behind test needs no normalization.

什么时候必须归一化：需要的是"多少"而不只是"正负"时。光照要的是 cos θ，所以 n 和 l 都必须是单位向量，否则一个长度为 2 的法线会让表面亮一倍。这就是上一课说"光照几乎都要求单位向量"的原因。

When you must normalize: whenever you need "how much", not just the sign. Lighting needs cos θ, so n and l must both be unit vectors; a normal of length 2 would make the surface twice as bright. That is why the last lesson said lighting expects unit vectors.

判断"在不在前面"：观察者在 E，朝向 f，目标在 T。先算从观察者指向目标的向量 d = T − E（1.1 课的"终点 − 起点"），再看 f · d：大于 0 在前面，小于 0 在后面。判断在不在视野锥里：把 f 和 d 都归一化，cos θ = f̂ · d̂ ≥ cos(视野角 / 2) 就看得见。

"Is it in front?": an observer stands at E, faces f, and the target is at T. First get the vector from observer to target, d = T − E (lesson 1.1's "end − start"), then check f · d: above 0 is in front, below 0 is behind. For a view cone, normalize both: the target is visible when cos θ = f̂ · d̂ ≥ cos(fov / 2).

    参考答案Reference answer 
      dot(v) { return this.x * v.x + this.y * v.y + this.z * v.z; }
  angleTo(v) {
    const d = this.length() * v.length();
    if (d === 0) return Math.PI / 2;               // 零向量没有方向，three.js 也这样约定
    const c = Math.min(1, Math.max(-1, this.dot(v) / d));   // 夹紧到 [-1, 1]
    return Math.acos(c);
  }
  projectOnto(b) {
    const bb = b.dot(b);
    return bb === 0 ? new Vec3(0, 0, 0) : b.scale(this.dot(b) / bb);
  }

function isInFront(eye, facing, target) {
  return facing.dot(target.sub(eye)) > 0;
}
function canSee(eye, facing, target, fovDeg) {
  const d = target.sub(eye).normalize(), f = facing.normalize();
  return f.dot(d) >= Math.cos(fovDeg / 2 * Math.PI / 180);
}

    Pitfalls常见误区Common mistakes

    • 以为点积是向量。点积的结果是一个数（标量）。"把两个向量逐分量相乘"得到的是另一种运算（分量乘积），不是点积。
    • 忘了归一化就当 cos θ 用。只有两个都是单位向量时 a · b 才等于 cos θ。判断正负可以不归一化，算亮度、算角度必须归一化。
    • acos 得到 NaN。浮点误差让余弦稍微超过 1 或 −1，Math.acos 就返回 NaN。先夹紧到 [−1, 1]。
    • 光照忘了 max(0, …)。背光面 n · l 是负数，不夹紧就会出现"负的光"，和其他光源相加时把画面减暗。
    • 用位置当方向。判断目标在不在前面，要用 T − E，而不是直接用 T。观察者不在原点时，直接用 T 的结果是错的。
    • Thinking the dot product is a vector. It is a single number (a scalar). Multiplying two vectors component by component gives a different operation (the component-wise product), not the dot product.
    • Using it as cos θ without normalizing. a · b equals cos θ only when both are unit vectors. The sign test works without normalizing; brightness and angles do not.
    • NaN from acos. Rounding pushes the cosine slightly past 1 or −1, and Math.acos returns NaN. Clamp to [−1, 1] first.
    • Forgetting max(0, …) in lighting. On the side facing away, n · l is negative. Without the clamp you get "negative light", which darkens the image when added to other lights.
    • Using a position as a direction. To test whether a target is in front, use T − E, not T itself. As soon as the observer is not at the origin, using T gives wrong answers.

    1. (2, −1, 3) · (1, 4, 0) 是多少？两者夹角大于还是小于 90°？1. What is (2, −1, 3) · (1, 4, 0)? Is the angle between them above or below 90°?

    2 − 4 + 0 = −2，是负数，所以夹角大于 90°。

    2 − 4 + 0 = −2. It is negative, so the angle is above 90°.

    2. 法线 n = (0, 1, 0)，光从正上方偏 60° 照下来，l 是单位向量。表面亮度（max(0, n · l)）是多少？2. The normal is n = (0, 1, 0) and the light comes in 60° from straight up, with l a unit vector. What is the brightness max(0, n · l)?

    n · l = cos 60° = 0.5，亮度是正对光时的一半。在演示 2 里把光源转到 60° 附近，边缘也是这样逐渐变暗的。

    n · l = cos 60° = 0.5, half the brightness of facing the light head-on. Demo 2 shows the same fall-off toward the edge of the sphere.

    3. 为什么判断"在前面还是后面"不需要归一化，但判断"在不在 90° 视野里"需要？3. Why does "in front or behind" need no normalization, while "inside a 90° field of view" does?

    前后只看正负，长度是正数，不改变符号。视野要和 cos 45° ≈ 0.707 比大小，长度会改变数值，必须先变成单位向量（或者把阈值乘上 |f||d|）。

    Front/behind only needs the sign, and lengths are positive so they cannot flip it. The field of view compares against cos 45° ≈ 0.707, and lengths change that value, so you must normalize first (or multiply the threshold by |f||d|).
