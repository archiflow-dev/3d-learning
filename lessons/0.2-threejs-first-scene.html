Math数学Math

three.js 的 fov 是垂直视角。在距离相机 d 的地方，画面从上到下能装下的世界高度是：

In three.js, fov is the vertical angle. At distance d from the camera, the visible world height from top to bottom is:

visibleHeight = 2 × d × tan(fov / 2)
visibleWidth  = visibleHeight × aspect      (aspect = canvasWidth / canvasHeight)

所以物体在屏幕上的大小大约和 1 / (d × tan(fov/2)) 成正比：离得越远、视角越大，物体看起来越小。把 fov 拉到 10° 像长焦镜头，拉到 120° 像鱼眼。只有落在 near 和 far 之间的东西才会被画出来，这一段空间叫视锥体（frustum），第 2.3 课会推导它的矩阵。

So an object's size on screen is roughly proportional to 1 / (d × tan(fov/2)): farther away or a wider angle makes it smaller. A 10° fov looks like a telephoto lens and 120° like a fisheye. Only things between near and far get drawn; that region is the view frustum, whose matrix we derive in lesson 2.3.

Task: complete build(THREE, group) to add a sphere (to the right of the cube, not overlapping it) and a point light (PointLight) so the side of the sphere near the light is clearly brighter. Run replaces only what you add; the original scene stays.

参考答案Reference answer 
function build(THREE, group) {
  const ball = new THREE.Mesh(
    new THREE.SphereGeometry(0.6, 32, 16),
    new THREE.MeshStandardMaterial({ color: 0xf4a261, roughness: 0.4 })
  );
  ball.position.set(2, 0.6, 0);
  group.add(ball);

  const bulb = new THREE.PointLight(0xffffff, 8, 0, 2); // 颜色, 强度, 距离, 衰减
  bulb.position.set(3.2, 1.6, 0.8);
  group.add(bulb);
}

检查方法：关掉上面的"灯光"开关，球体朝着你那盏灯的一侧应该仍然是亮的。如果球是全黑的，说明灯太远、太暗，或者放到球的背面去了。

Check: switch off the "Lights" box above. The side of the sphere facing your light should still be lit. If the sphere is completely black, the light is too far, too dim, or behind the sphere.

Pitfalls常见误区Common mistakes

  • 物体全黑。MeshStandardMaterial 要靠灯光算颜色，没有灯就是黑的；MeshBasicMaterial 不受光，永远是同一个颜色。在上面切换材质并关灯就能看到区别。
  • 画面被拉扁。窗口大小变了，但没有更新 camera.aspect 并调用 camera.updateProjectionMatrix()。改了相机的任何参数，都要调用这个函数。
  • near 设成 0 或特别小。透视投影里 near 不能是 0，太小会让深度精度变差，远处的面互相闪烁（z-fighting）。第 2.4 课会解释原因。
  • 画面模糊。高分屏上要调用 renderer.setPixelRatio(devicePixelRatio)，原因和上一课讲的"Canvas 有两个尺寸"一样。
  • Everything is black. MeshStandardMaterial needs lights to compute color, so with no light it is black. MeshBasicMaterial ignores lights and always shows one flat color. Switch the material above and turn the lights off to see the difference.
  • The image looks squashed. The window size changed but camera.aspect was not updated and camera.updateProjectionMatrix() not called. Call it after changing any camera parameter.
  • near set to 0 or very small. A perspective camera cannot have near = 0, and a tiny value wrecks depth precision so distant faces flicker against each other (z-fighting). Lesson 2.4 explains why.
  • The image is blurry. On high-DPI screens call renderer.setPixelRatio(devicePixelRatio), for the same reason as last lesson's "a canvas has two sizes".

3. 为什么每一帧都要调用 renderer.render(scene, camera)，而不是只调用一次？3. Why call renderer.render(scene, camera) every frame instead of once?

帧缓冲只是一张图。物体转动、相机移动之后，旧的图不会自己更新，必须重新算一遍所有像素。这个"每帧重画"的循环就是渲染循环。

The framebuffer is just an image. After objects or the camera move, the old image does not update itself; every pixel has to be computed again. That redraw-every-frame cycle is the render loop.
