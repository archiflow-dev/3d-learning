# 教学笔记：ArchiFlow 的学习方式和我的教学改进

> 用途：每次开始一课（或给课程加内容）之前，先读这份文件，按「教学规则」做。每次课程结束后，在「观察日志」末尾补一条，必要时修改规则。
> 写法约定：**事实**是对话里真实发生过的；**推断**是我根据事实做的判断，可能错，要继续验证。

最近更新：2026-11-09（1.1 到 1.7 课）

---

## 1. 学习者画像（事实）

- 目标：系统学 3D 数学、图形学和渲染，最终服务于 Web 3D、建筑和产品可视化、游戏、3D Gaussian Splatting。
- 用中文交流；要求先复述他的目标，并要求直接、批判性的反馈，不要空洞的夸奖。
- 常在深夜学习（UTC 01:00–02:00 前后），一次会话很长，一晚上能连续追问五六层。
- 除了学内容，也会关心课程网站本身（发现过首页课程列表不显示的 bug）。

## 2. 学习模式（事实 + 推断）

### 2.1 一路往下追问，直到碰到地基
- **事实**：1.7 课的一个晚上，问题链是：逆转置 → 「n · x = d 是什么」 → 「(M⁻¹)ᵀ 详细讲」 → 「为什么转置能跨过点积，逆转置的几何和物理意义」 → 「矩阵求逆怎么做」 → 「全部加进课程，并做成动画」。
- **事实**：1.5 课问过「det() 到底做什么用的，我理解有点模糊」，接着问「det 主要应用在什么地方」。
- **推断**：他不满足于会用公式，要一直追到「这个东西本质上是什么」。每遇到一个新符号或新运算，他都会问同一组问题（见 2.2）。

### 2.2 固定的「四问」
- **事实**：原话是「怎样计算？为什么用它？怎么用它？它到底表示了什么？」
- 再加上他反复要求的几何意义和物理意义，一个概念完整的讲解应该包括：**怎么算、为什么、怎么用、本质是什么、几何意义、物理意义、在图形学里的用途**。

### 2.3 要看得见，要能动手拖
- **事实**：主动要求过以下这些可视化：
  - 「为什么」一节要用 3Blue1Brown 的风格；
  - 1.6 课的 2D 剪切演示；
  - 「2D 仿射矩阵里每个元素和平移、旋转、缩放的关系」；
  - 「用动画演示计算过程，特别是求逆和转置」。
- **推断**：静态公式对他不够。他要看到每个数的变化对应画面上的什么变化。

### 2.4 直觉对，措辞和形式化容易出错
- **事实**：
  - 1.6 课：直觉「先把点移到原点」是对的，但代码写成了 T(−p)·R·T(p)。复述时把中间的旋转说成「移动」；说法线「会移动」而不是「方向和长度变了」。
  - 1.5 课：把叉积的方向说成「角度」。
  - 1.3 课：把「法线朝向相机」和「法线沿视线方向」搞混了。
  - 1.2 课：canSee 里把弧度和角度混用了。
- **推断**：他的空间直觉不错，薄弱的是：
  1. 约定和顺序：写的顺序 vs 执行的顺序，弧度 vs 角度，行优先 vs 列优先；
  2. 用精确的词复述；
  3. 代数推导：比如第 4 行和 w 的那道题，他直接说「这个我不太明白」。

### 2.5 代码习惯
- **事实**：1.1 到 1.5 课的代码常和参考答案相同。1.6 课开始自己写，写法明显不同，错误也因此暴露出来，自己改正了。
- **推断**：自己写代码的效果明显更好，评审时应该继续鼓励他自己写，并把错误当成教学素材。

### 2.6 前置知识的缺口会在课中突然冒出来
- **事实**：1.7 课用到了 (M⁻¹)ᵀ，但求逆和转置从没正式讲过（1.5 课只讲了 det）。结果他花了一整晚补这两块。
- **推断**：这是**我**备课的漏洞，不是他的问题。

## 3. 我学到的：作为老师要注意什么

1. **备课时先做前置审计**：列出这课用到的每一个符号和运算，逐个检查前面的课有没有讲过。没讲过的，就在课里加一个「补课」小节，并配动画。
2. **每个新概念默认按「七问」准备**：怎么算（配动画）、为什么（推导）、怎么用（代码和 three.js）、本质是什么、几何意义、物理意义、常见错误。这样他追问时，课程里已经有答案。
3. **计算过程默认做成动画**：矩阵运算、推导步骤要能单步播放或自动播放，并标出每一步改了什么。
4. **约定和顺序单独强调**：凡是涉及顺序、单位、存储方式的地方，都放一个「容易反」的提示，并在游戏里设计一关专门暴露这个误解。
5. **评审时要求精确措辞**：直觉对、但说法不准时，指出具体哪个词不准，并请他用正确的词再说一遍。不能因为大意对就算过。
6. **诚实记录谁讲的**：`.mine` 评审记录里写清楚哪些是他答出来的，哪些是我讲的。
7. **回答追问时先说结论，再分层展开，最后给一个手算例子**。他喜欢详细的解释，但每层都要能单独看懂。

## 4. 可执行的方案（从 1.8 课开始）

每一课都增加下面三样东西：

### 4.1 「你可能会问」盒子
3 到 5 个可展开的问题，根据他的追问模式预判，比如「这东西本质上是什么」「为什么非要这样算」「它在物理里对应什么」「换个约定会怎样」。每个问题都附上答案。

### 4.2 「意想不到的联系」卡片
每课至少一个跨领域的惊喜。已经用过的：倒格子就是 2π(A⁻¹)ᵀ；法线是余向量。

### 4.3 「下一层」提示
课程末尾写 1 到 2 句，说明这个概念以后会在哪里再出现、会变成什么样，引导他主动往深处想。

### 4.4 开课和收尾的流程
- **开课前**：读这份文件，做前置审计，按「七问」检查每个新概念。
- **评审时**：理解题里至少有 1 题考约定或顺序，1 题要求他用精确的词复述。
- **结束后**：在下面的「观察日志」里记一条：他问了什么、卡在哪、哪个预判命中了、哪个没命中。

## 5. 对后续课程的预判（推断，用来提前准备「你可能会问」）

- **1.8 Rodrigues 公式**：
  - 为什么公式里有叉积项和 (1 − cosθ) 项？
  - 它和「先把轴转到 z、绕 z 转、再转回来」是什么关系？（这正好是 1.6 和 1.7 的三明治写法）
  - 旋转矩阵为什么是正交矩阵？（对应本课 Rᵀ = R⁻¹）
- **1.9 欧拉角、四元数**：
  - 四元数「到底是什么」，为什么是 4 维？
  - 为什么要写成 q v q*，为什么用半角？
  - q 和 −q 为什么表示同一个旋转？
  - 万向锁在物理上是什么？（惊喜素材：阿波罗 11 号的陀螺仪平台真的担心过万向锁，讲之前要先核实细节）
- **1.10 求交**：射线和平面求交，直接用 n · x = d（本课已讲）。Möller–Trumbore 算法里的 det 和叉积，对应 1.3 和 1.5 课。
- **2.x 相机**：
  - 视图矩阵为什么是相机矩阵的逆？（对应 (T·R)⁻¹ = R⁻¹·T⁻¹）
  - 透视除法里的 w 是什么？（1.6 课已经预告过）
  - 深度为什么是非线性的？
  - 着色器里的 normalMatrix 为什么用 modelView 的逆转置？
