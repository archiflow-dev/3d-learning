Intuition直觉Intuition

向量就是一支箭头：它说"往哪个方向、走多远"，但不说"从哪里出发"。把同一支箭头平移到任何地方，它还是同一个向量。点则相反，它只说"在哪里"。

A vector is an arrow: it says "which way and how far" but not "starting from where". Slide the same arrow anywhere and it is still the same vector. A point is the opposite: it only says "where".

图形学里几乎所有东西都是这两种之一：顶点位置是点；光照方向、表面法线、相机朝向、速度都是向量。上一课 three.js 里的 position.set(3, 0.6, 0) 是点，后面要学的 lookAt 用的就是"目标点 − 相机位置"得到的向量。

Nearly everything in graphics is one of the two: vertex positions are points; light directions, surface normals, camera directions and velocities are vectors. Last lesson's position.set(3, 0.6, 0) is a point, and the lookAt we meet later uses the vector "target point − camera position".

Math数学Math

所有运算都是逐分量进行的（3D 时多一个 z，规则完全一样）：

Every operation works component by component (3D just adds a z with the same rules):

a + b = (aₓ + bₓ, a_y + b_y)
a − b = (aₓ − bₓ, a_y − b_y)
k · a = (k·aₓ, k·a_y)
|a|   = √(aₓ² + a_y²)              ← 勾股定理 / Pythagoras
â     = a / |a|                     ← 方向不变，长度变成 1 / same direction, length 1

a − b 的几何意义：从 b 的箭头尖指向 a 的箭头尖。这就是"点 − 点 = 向量"：两个位置相减，得到从一个指向另一个的位移。

What a − b means: the arrow from the tip of b to the tip of a. That is "point − point = vector": subtracting two positions gives the displacement from one to the other.

归一化之后的向量叫单位向量，只表示方向。光照、法线计算几乎都要求输入是单位向量，下一课的点积会解释原因。

A normalized vector is a unit vector and carries direction only. Lighting and normal math almost always expect unit vectors; next lesson's dot product shows why.

Task: write a Vec3 class with add, sub, scale, length and normalize. Every method returns a new vector and leaves the original unchanged. Normalizing the zero vector returns (0, 0, 0), never NaN. Press "Run tests" and the page checks each one. You will keep using this class, and it becomes the math library of your own renderer.

    参考答案Reference answer 
    class Vec3 {
  constructor(x = 0, y = 0, z = 0) { this.x = x; this.y = y; this.z = z; }
  add(v)   { return new Vec3(this.x + v.x, this.y + v.y, this.z + v.z); }
  sub(v)   { return new Vec3(this.x - v.x, this.y - v.y, this.z - v.z); }
  scale(k) { return new Vec3(this.x * k, this.y * k, this.z * k); }
  length() { return Math.hypot(this.x, this.y, this.z); }
  normalize() {
    const len = this.length();
    return len === 0 ? new Vec3(0, 0, 0) : this.scale(1 / len);
  }
}

    Pitfalls常见误区Common mistakes

    • 归一化零向量。长度是 0，除以 0 得到 NaN，NaN 会沿着后面所有计算一路传下去，最后画面上出现黑点或整个物体消失，很难查。
    • 把点和向量混用。"点 + 点"没有几何意义（两个位置相加是什么？）。第 1.6 课会用第 4 个分量 w 区分两者：点的 w = 1，向量的 w = 0，平移只作用在点上。
    • 方法悄悄修改了自己。如果 a.add(b) 改掉了 a，后面再用 a 时就是错的值。three.js 的 Vector3.add 就是会修改自己的，这是它最常见的坑之一，所以我们的类故意设计成返回新对象。
    • 只为比较远近还开平方。比较两个距离谁大时，比较长度的平方就够了，可以省掉开方。
    • Normalizing the zero vector. Its length is 0, dividing by 0 gives NaN, and NaN spreads through every later calculation until black pixels appear or a whole object vanishes. It is hard to trace.
    • Mixing up points and vectors. "Point + point" has no geometric meaning (what is the sum of two places?). Lesson 1.6 separates them with a fourth component w: points have w = 1, vectors w = 0, and translation only moves points.
    • Methods that quietly modify the original. If a.add(b) changes a, every later use of a is wrong. three.js's Vector3.add does modify in place, one of its most common traps, which is why our class returns new objects on purpose.
    • Taking a square root just to compare distances. To see which of two distances is larger, comparing squared lengths is enough and skips the square root.

    1. 向量 (1, 2, 2) 的长度是多少？归一化后是什么？1. What is the length of (1, 2, 2), and what is it normalized?

    √(1 + 4 + 4) = 3; normalized it is (1/3, 2/3, 2/3).

    2. 相机在点 C = (1, 1)，目标在点 T = (4, 5)。从相机指向目标的向量是什么？距离是多少？2. The camera is at C = (1, 1) and the target at T = (4, 5). What vector points from camera to target, and how far is it?

    T − C = (3, 4)，距离是 √(9 + 16) = 5。注意顺序：从 C 指向 T，是 T − C，不是 C − T。

    T − C = (3, 4), at distance √(9 + 16) = 5. Mind the order: from C to T is T − C, not C − T.

    3. 把一个向量乘以 −1，会发生什么？3. What happens when you multiply a vector by −1?

    Same length, opposite direction. Pick k · a in the demo and drag k to −1.
