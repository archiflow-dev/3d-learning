Intuition直觉Intuition

计算机图形学做三件事：用数字描述一个世界（建模），让它随时间变化（动画），再把它变成一张图（渲染）。不管前面多复杂，渲染最后的产物都一样：一个由像素组成的矩形网格，每个格子存一个颜色。这个网格在内存里叫帧缓冲（framebuffer）。

Computer graphics does three things: describe a world with numbers (modeling), change it over time (animation), and turn it into a picture (rendering). However complex the first two get, rendering always ends in the same place: a rectangular grid of pixels, each holding one color. In memory that grid is called the framebuffer.

所以后面所有的课，最终都在回答同一个问题：这个像素应该是什么颜色？

So every later lesson answers one question in the end: what color should this pixel be?

Math数学Math

宽 W、高 H 的帧缓冲在内存里是一行接一行排好的一维数组。浏览器的 ImageData 每个像素占 4 个字节（R、G、B、A），所以：

A framebuffer of width W and height H is stored as a 1D array, one row after another. In the browser's ImageData each pixel takes 4 bytes (R, G, B, A), so:

index(x, y) = (y × W + x) × 4

Canvas 的原点在左上角，y 往下增大；数学和 OpenGL 习惯原点在左下角，y 往上增大。两者的换算：

Canvas puts the origin at the top left with y growing downward; math and OpenGL put it at the bottom left with y growing upward. To convert:

y_up = H − 1 − y_down

减 1 是因为像素下标从 0 开始，最后一行是 H − 1。

The −1 is there because pixel indices start at 0, so the last row is H − 1.

Exercise你动手Your turn

任务：补全 shade(x, y, W, H)，返回 [r, g, b]（0–255），让画面从左到右红色变强，从下到上绿色变强。注意第二个条件要用 y 朝上的约定。先自己写，写完再看下面的参考答案。

Task: complete shade(x, y, W, H) so it returns [r, g, b] (0–255) where red grows from left to right and green grows from bottom to top. The second part needs the y-up convention. Write it yourself before opening the reference answer.

我的解答（2026-11-03）My solution (2026-11-03)

function shade(x, y, W, H) {
  const y_up = H - 1 - y;
  const r = Math.round(255 * x / (W - 1));
  const g = Math.round(255 * y_up / (H - 1));
  return [r, g, 0];
}

评审时学到的：写成 H − y 会让每一行都往上错一行，最上面一行越界，最下面一行永远是空的。(x + 0.5) / W 是在像素中心取样，两端分别是一点点红和略低于 255，永远不会超过 255；需要两端正好是 0 和 255 时用 x / (W − 1)，在连续函数上取样（光栅化、光追、纹理）时用像素中心。ImageData 用的是 Uint8ClampedArray，写入小数时会自动限制在 0–255 并取整，不会报错，所以去掉 Math.round 结果几乎不变。

What the review taught me: writing H − y shifts every row up by one, so the top row falls off the buffer and the bottom row stays empty. (x + 0.5) / W samples at pixel centers: the ends get a little red and slightly under 255, never above it. Use x / (W − 1) when the ends must be exactly 0 and 255, and pixel centers when sampling a continuous function (rasterization, ray tracing, textures). ImageData is a Uint8ClampedArray, which clamps written values to 0–255 and rounds them without any error, so dropping Math.round barely changes the result.

参考答案Reference answer 
function shade(x, y, W, H) {
  const yUp = H - 1 - y;
  const r = Math.round(255 * x / (W - 1));
  const g = Math.round(255 * yUp / (H - 1));
  return [r, g, 0];
}

检查方法：左下角应该是黑色，右上角是黄色（红 + 绿）。

Check: the bottom-left corner should be black and the top-right yellow (red + green).

Pitfalls常见误区Common mistakes

  • 像素不是一个点，是一个小方格。像素 (3, 2) 的中心在 (3.5, 2.5)。光栅化和光追里经常要用中心坐标，忘了加 0.5 会让整个画面偏半个像素。
  • Canvas 有两个尺寸。width/height 属性是帧缓冲的真实像素数，CSS 宽高只是显示时的缩放。两者不一致时，画面会被拉伸或模糊。
  • y 轴方向要在每个项目开头就定下来。后面从 Canvas 换到 WebGL 时，纹理上下颠倒几乎都是这个原因。
  • A pixel is a small square, not a point. Pixel (3, 2) has its center at (3.5, 2.5). Rasterizers and ray tracers sample at centers; forgetting the 0.5 shifts the whole image by half a pixel.
  • A canvas has two sizes. The width/height attributes are the framebuffer's real pixel count; the CSS size only scales the display. When they differ, the image stretches or blurs.
  • Decide the y direction at the start of every project. When you move from Canvas to WebGL, upside-down textures almost always come from this.
